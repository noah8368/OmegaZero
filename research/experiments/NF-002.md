## Question

Can we produce clean `(x, u)` training examples end-to-end — position → eval-actually-
used → stronger-search target `v*` → error `u` → feature representation `x` — using the
*current* engine as a stand-in, so the whole pipeline is debugged before the real NNUE
net lands and we re-run on the true embedding?

The methodology is net-agnostic, so building it now (against HCE / the existing net) is
free scheduling: it converts three weeks of waiting into a debugged data pipeline.

## Design decisions — SETTLED 2026-08-08

- **Target evaluation to model:** error of the **raw static eval** (`board_->Evaluate()`)
  — *not* the corrected eval, *not* qsearch. This is a pure, deterministic function of
  position (no path-dependent correction term → clean, reproducible labels). Rationale:
  the model **replaces** correction history (H6) rather than layering on it — its mean
  subsumes corr-hist's job, its quantiles feed margins. See
  [../notes/correction_history.md](../notes/correction_history.md).
  - *Superseded:* the proposal's qsearch-eval target — OmegaZero's margins key off static
    eval, not qsearch (only razoring drops into qsearch).
- **Sign of the target:** model **signed** error `v̂ − v*` (H3). Store raw `v̂` and `v*`
  so absolute is derivable for free.
- **`v*` source:** **fixed-depth deep OmegaZero** search (H4), with a **node cap** as a
  safety valve so tactical explosions don't stall datagen. No Stockfish target (ground-
  truth calibration study deferred).
- **Feature `x`:** placeholder now (whatever the current eval exposes); the real hook is
  the trained NNUE accumulator / hidden layer — add the C++ extraction point but expect
  to re-run once the net exists.
- **Correction-noise metadata:** record the corr-hist correction that *would* apply, so
  we can quantify how much path-dependent noise it adds (relevant to eval-correction
  calibration even though we model raw-eval error).
- **Sampling:** subsample ~1 position / 8–16 plies (or random per game) to cut
  intra-game correlation.
- **Split:** by **game**, never by position (neighboring plies leak).

## Data strategy — DECIDED 2026-08-14

Generate a **fresh ~10M-position** dataset with the trained NNUE engine, rather than
reusing the 87M HCE corpus. Rationale: the fresh run is generated by the deployment engine
(correct eval version, no covariate shift), lets us write `v*` at generation time, and —
decisively — is **disjoint from the NNUE training set**, so the measured error `u` isn't
biased optimistically low (the leakage trap; see "Re-using the existing NNUE datagen").

- **Model:** frozen NNUE trunk (= the embedding `x`) + a fresh **MDN head** (per H2), folded
  into the existing forward pass (H5).
  - *Init the trunk from the trained NNUE checkpoint, then **freeze** it*; the head is new
    (NNUE's own head is a single eval scalar, so nothing to copy into a 15-output MDN head).
  - *Init the head so its **mean ≈ 0*** → `corrected_eval ≈ raw_eval` at step 0; it learns
    the correction from there (matters for the H6 mean-replaces-corr-hist swap).
  - *Sequence **freeze-first, unfreeze-as-fallback***: a frozen eval-trunk encodes features
    tuned for *eval*, not *error*; fine-tune the trunk only if the frozen head underfits.
    (Prior it won't need to: corr-hist conditions on just a pawn hash and still helps.)
- **Sizing:** 10M is at/above the central band and, with a frozen (tiny) head, comfortable
  even for a tight `C≈0.99`, with room for a by-game validation holdout. See "Data sizing".
- **`v*` generation:** **amortize** the fixed-depth + node-capped `v*` search over the
  sampling interval — play the game normally, and only at each *kept* position (~1/8–16
  plies) run the deep `v*` search, capture `v̂ = Board::Evaluate()` (free), and write
  `FEN, stm, v̂, v*, u=v̂−v*, depth/nodes/phase` directly (no recompute pass).
- **⚠️ Invert the tactical filters:** the NNUE datagen *excludes* in-check / `|score|>3000`
  / tactical explosions to get clean value targets — but those are exactly where the **fat
  upper tail of `u`** (what the margins read) lives. **Relax** them here (exclude only true
  mate scores; **tag** kept tactical positions so the tail is studyable). ProbCut dropped
  these to fit a clean Gaussian; we're modeling the non-Gaussian tail, so we keep them.
- **Open knob (decide later):** which layer is `x` — the incrementally-maintained
  **accumulator** (cheapest per node → best for H5 NPS) vs. a deeper hidden layer (richer,
  needs the full forward pass).

The 87M HCE corpus is demoted to an optional **throwaway pilot** to shake out the label
pipeline before the net exists (see "Re-using the existing NNUE datagen").

## Datagen audit — what's already stored vs. what NF-002 needs (2026-08-14)

Read `src/datagen.cc`, `scripts/preprocess_data.py`, `src/engine.h`, `src/board.h`.

**Row format written today** (`datagen.cc:474`): `FEN | score | result`, space-pipe-space
delimited, consumed by `preprocess_data.py` (`parts = line.split(" | ")`, dtype
`score:int16`, `result:uint8` ∈ {0,1,2}).
- `score` = a **time-limited search score** — `engine.GetBestMove(score_stm)` at `st`
  (default **0.5 s/move**), converted to **White POV** (`datagen.cc:215`). It is *not* the
  static eval and *not* a fixed-depth target.
- `result` = game outcome, White POV (1.0/0.5/0.0).

**Reusable infrastructure already in place** (matches NF-002's sampling spec for free):
skip first 10 plies, sample **1/4** eligible plies, skip in-check, skip `|score|>3000`
(tactical explosions) and mate-ish scores, per-worker Zobrist **dedup**, and — crucially —
**split by game** via `val_fraction` (`val_start_game`, `datagen.cc:455`). NF-002's
"split by game, never by position; subsample ~1/8–16" is essentially the existing harness
(bump `kSampleInterval` 4 → 8–16).

**Free for NF-002:** FEN, a search value, result, and the whole
sample/dedup/by-game-split pipeline.

**Missing — must be added:**
1. **`v̂` (raw static eval)** — *not* stored. `Board::Evaluate()` (`board.h:188`) is exactly
   the raw, **uncorrected** static eval NF-002 targets: `GetCorrectedEval` lives in
   `Engine`, so `Evaluate()` is pre-correction. One deterministic call per sampled
   position — **cheap**. (Confirm POV; keep everything STM-relative since pruning reads
   STM-relative scores.)
2. **`v*` as fixed-depth deep search** — the stored score is **time-based**
   (non-deterministic, machine/load dependent), not the fixed-depth + node-cap target H4
   specifies. Good news: `Engine::SetDepthLimit(int)` (`engine.h:195`) already exists and
   the engine honors a depth/node limit, so deterministic fixed-depth `v*` is a **wiring
   change, not new search code**. This adds a second (deep) search per sampled position —
   the **main compute cost** of NF-002 datagen.
3. **Feature `x`** — the NNUE embedding hook is absent entirely; placeholder until the net
   exists (expected — re-run on the real embedding later).
4. **Metadata** (depth reached, nodes, phase, side-to-move [derivable from FEN], and the
   corr-hist correction that *would* apply) — none stored; add for the calibration studies.

**Design decision surfaced:** the existing score is a *search* score, and search uses
`GetCorrectedEval` internally, so it already bakes in correction history — it **cannot**
double as `v̂` (which must be the raw static eval). We must capture `Evaluate()` separately.
The existing time-based score could serve as a `v*` *proxy* if we tolerated its
non-determinism, but the clean path is a dedicated fixed-depth search.

**Recommended NF-002 datagen shape:** add an "uncertainty-label" datagen mode that, per
sampled position, emits `FEN, stm, v̂=Evaluate(), v*=fixed-depth-search, u=v̂−v*` plus
`depth/nodes/phase/would-be-corr-hist` — POV kept consistent (STM). Reuse the existing
sampling/dedup/by-game split verbatim. Model (per H2) is the **MDN** head; flow = backstop.

## Data sizing — how many `(x, u)` labels do we need? (2026-08-14)

Order-of-magnitude estimate, anchored on ProbCut (the analogous constant-margin method)
and the full-NNUE pole. Stated assumptions, not a precise number; the deployed risk level
`C` is the dominant knob.

**Anchors.**
- **ProbCut, chess** (Jiang & Buro, *First Experimental Results of ProbCut Applied to
  Chess*): fit one Gaussian error model `v' = a·v + b + e`, `e~N(0,σ)` per **stratum**
  (depth-pair × phase × score-range) from **~2,700 positions** (full α-β, Crafty). Notably
  they **excluded** mate-in-N positions (~1/1000) from the regression, and found **σ is
  depth-pair dependent**. → the *unconditional / lightly-stratified constant* pole (= our
  H1/H4 SPSA-tuned-`C` baseline).
- **Multi-ProbCut, Othello** (Buro): per-depth-pair Gaussian MLE from a game DB, ~O(10⁴).
- **Modern constant-margin ProbCut** (Stockfish): scalar margin, SPSA-tuned over O(10⁴–10⁵)
  self-play *games*. = our H1 baseline.
- **Full NNUE net:** 10⁸–10⁹ positions (eval from scratch).

Our model sits between the ProbCut pole and the NNUE pole: a full conditional distribution
`p(u|x)` (MDN K=5, ~15 outputs) over a **rich frozen NNUE embedding**, on a **residual**
target (embedding already did the structural work) → far below full-NNUE scale, far above
ProbCut's 2,700.

**Two drivers.**
1. *Params:* head on `d≈256–1024` embedding = ~4k (linear) to ~70k (small MLP); at
   100–1000 samples/param for a density-with-tails → ~1–15M.
2. *Tail-limited effective sample (binding):* a margin reads a one-sided quantile at `C`;
   only `(1−C)` of samples inform it per x-region. For ~10³ tail events across ~10²–10³
   effective regions: `N ≈ 10³·10³/(1−C)` ≈ **2×10⁷ at C=0.95**, ×5 at C=0.99, ~5–10×
   cheaper at C=0.90.

**Recommended figures.**

| Stage | Target | Positions | Rationale |
|---|---|---|---|
| NF-002 dry run | pipeline + first calibration read | **10⁴–10⁵** | ProbCut-scale; validate labels/PIT/coverage at moderate C |
| NF-003 corrector-swap (mean, H6) | conditional mean replaces corr-hist | **10⁵–10⁶** | mean is an easy target (ProbCut difficulty × conditioning) |
| NF-004 margins (tails, H1) | usable conditional quantiles | **~2–5M** central; up to **~10⁷** for tight C=0.99 | tail-limited; scales with deployed `C` |
| diminishing returns | — | **~10⁷** | beyond this, fixed-depth `v*` **label noise** dominates, not volume |

**Central answer: ~2–5M labeled `(x, u)` pairs** for the headline margin result, front-loaded
by a 10⁴–10⁵ pilot; push toward 10⁷ only for high-`C` deployment.

**Cost reality.** Volume isn't the bottleneck — the **deep fixed-depth `v*` search per label**
is. But the mean (NF-003) and pilot (NF-002) need ≤10⁶ and can start now on the current eval;
the tail-accurate 2–5M set can be **co-generated during the ~100M NNUE datagen campaign**
(subsample ~1/20–1/50 *with an added deep target search*). Two datagen-design carry-overs
from ProbCut: (a) a mate/tactical-score exclusion policy for the signed-error tails;
(b) label noise scales with `v*` depth, capping useful volume.

Sources: Jiang & Buro, *First Experimental Results of ProbCut Applied to Chess*
(`cs.ubc.ca/~jiang/papers/mpc_main.pdf`); Buro, *Experiments with Multi-ProbCut ... Othello*
(`skatgame.net/mburo/ps/mpc.pdf`); Chessprogramming wiki, *ProbCut*.

## Re-using the existing NNUE datagen (2026-08-14) — PILOT ONLY

**Superseded as the primary dataset** by "Data strategy — DECIDED" (fresh 10M, leakage-free).
Kept as the option for a throwaway pilot before the net exists. The leakage caveat below is
exactly *why* the real dataset is generated fresh.

There are **~87M curated positions** on disk (`nnue/data/combined/training_data.txt`,
`FEN | score | result`), generated by commit `30e674a` (2026-07-15) with **HCE** (no
`nnue.bin` at that commit → the stored `score` is an HCE-based 0.5s search score).

**Reusable — the *positions*, not the *labels*.** The FEN corpus is the asset; everything
on the conditioning side of `(x, u)` is a deterministic function of the FEN and is
recomputable cheaply. Only `v*` needs fresh compute — the part we pay for anyway.

| NF-002 field | Reusable? | How |
|---|---|---|
| **87M FENs** | ✅ directly | skips the expensive half of datagen (playing self-play games at 0.5s/move, most compute on *discarded* moves); already deduped + quality-filtered |
| **v̂ (raw static eval)** | ✅ recompute | `Board::Evaluate()` per FEN, deterministic ~µs; 87M ≈ minutes single-core |
| **x (NNUE embedding)** | ✅ recompute later | forward-pass each FEN once the net exists |
| phase / stm / material | ✅ derive from FEN | — |
| **v\* (fixed-depth target)** | ❌ regenerate | stored `score` is time-limited 0.5s, non-deterministic, corr-hist-baked → only a throwaway `v*` *proxy* for the pilot; clean H4 target needs a fresh fixed-depth search per position (the real NF-002 cost, but paid **only on kept positions** — more efficient than fresh datagen) |
| depth / nodes / PV | ❌ lost | — |

**Two caveats.**
1. **Do not reuse the stored `score` as `v̂` or `v*`** — it's HCE-based; recompute both with
   the current engine so `u = v̂ − v*` is self-consistent. Positions are engine-agnostic;
   labels are not.
2. **⚠️ Train/test leakage for the final NNUE-embedding model.** These exact FENs *trained*
   the NNUE, so measuring `u` on them with `x = NNUE(position)` biases the error
   **optimistically low** → **underestimates uncertainty**, the opposite of what a safe
   pruning margin needs. Fine for the pilot and the mean (NF-003); for **NF-004's final
   margin model, draw positions disjoint from the NNUE training set** (fresh datagen or a
   held-out pool). `validation_data.txt` is 0 B in these runs — the leakage-free split lives
   elsewhere (`dedup_validation.sh`).

**Upshot per stage:** NF-002 pilot — subsample ~10⁴–10⁵ of the 87M FENs now (recompute v̂,
scratch `v*` proxy), zero new game-play. NF-003 (mean) — reuse FENs, recompute v̂ + a real
fixed-depth v*. NF-004 (final) — NNUE-training-disjoint positions.

## Setup / Results / Interpretation

**Pilot run 2026-08-15 (harness verification — NOT a coherent research read).** Labels are
HCE-eval error (no `nnue.bin` at datagen time); the conditioning embedding is from a weak,
overfit NNUE trunk → embedding and labels describe *different* evals. Purpose: prove the
pipeline runs end-to-end and the head calibrates.

- **Data:** 34,479 positions (31,011 train / 3,468 val, split by game), depth-8 `v*`,
  `nnue/data_uncertainty/combined/`. Fat tail intact (|u|≥600cp = 2.6%, max 2209cp).
- **Trunk / embedding:** `2026-06-07…61d0444_6.0M_pos/best.bin`, 512-dim STM-relative accum
  reconstructed from the quantized FT block (int16/127, clamp[0,1]).
- **Model:** `mdn_t` K=5 Student-t head (`research/experiments/nf002_fit_pilot.py`).
- **Results:** conditional vs unconditional-floor — val **NLL 1.023 vs 1.102** (+0.079);
  pinball qMAE lower at τ=.1/.5/.9; coverage near nominal (90/95% on the nose, 50%→44%);
  PIT KS 0.044. Slight overfit (early stop epoch 13; 31k is small).
- **Interpretation:** the frozen trunk carries signal about `u` and the calibration pipeline
  is sound. Numbers are not a research read — a coherent one needs NNUE-eval labels (regen
  datagen with `nnue.bin`). Harness core (head/loss/embedding/diagnostics) is prod-reusable;
  its plumbing (HCE labels, Python per-record embed, in-RAM, no C++ inference) is not.
