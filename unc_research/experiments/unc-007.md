## Question

Does the trained head, deployed through a **single fused NNUE+head `.bin`** and a **C++ handle** that
runs the full network, produce position-conditional `p(u|x)` that (i) matches the Python reference head
within tolerance (**port parity** — the hard gate), (ii) varies in the **a-priori-expected direction**
across curated position types (sharp ≫ quiet in spread), (iii) has `E[u|x]` **pointing the right way**
on known static-eval blind spots, and (iv) **covers** the realized `u = v − v*` at ≈ nominal rates
across the set? This is the deployment/qualitative validation that must pass before the grain-quantized
integer head (H5 Milestone B) and the margin wiring (H1) are worth building.

## Why this experiment, and why now

unc-002/unc-006 validate the head **offline in Python on the val split**. Nothing yet proves the head
behaves the same way **in the engine**, on **arbitrary interpretable positions** a human can reason
about. unc-007 closes both gaps at once: it forces the deployed C++ path into existence (the fused bin
+ handle — the thing every downstream H1/H6/H7 consumer needs anyway), and it turns the head loose on a
hand-built position set where we have a *prior* about what the answer should be. A plot where a fortress
and a forced tactic get the same spread is a falsification signal, not decoration.

**Honest quantitative ceiling.** Arbitrary curated FENs have **no `v*` ground truth**, so full
fold-level calibration (unc-002/006) is impossible on them. Fix: the harness **also computes `v*`** per
FEN (the same fixed-depth + node-capped deep search datagen uses), yielding one realized `u = v − v*`
per position. That converts the study from purely qualitative to *coarsely* quantitative — one PIT
sample per FEN, hence a set-level coverage/PIT check (small `N`, so a coarse gate, not unc-002's fold
calibration). This is "the best quantitative analysis the data allows."

## Setup

Frozen from unc-002: the trained `mdn_t` head (`best.bin`, OZUH), the `nnue.bin` trunk (**md5 must
match the head's baked `trunk_md5`**), and the embedding recipe. **No new datagen for the labels** — the
only search run is the per-FEN `v*` the harness computes on the curated set (~tens of positions).

**Pipeline (each stage is a goal; see Workplan):**

1. **Fused `.bin` (`OZNU`).** One self-contained file: the **full `nnue.bin` (all layers, not just the
   feature transformer)** + the head, behind a combined header — `magic "OZNU"` (constant format tag),
   `version`, **`run_id`** (a **free-form, author-chosen provenance string**, e.g. `<ts>_<gitsha>_<datatag>`
   but not a fixed schema), section offsets, echoed `trunk_md5`. The **same `run_id` field is present on
   every OZ\* file** (OZNN, OZUH, OZNU), so each self-identifies; because OZNU embeds the full OZNN section,
   its own `run_id` (the head run) + the embedded trunk's `run_id` form a **provenance chain**. Each payload
   keeps its own `OZNN`/`OZUH` magic so sub-sections stay independently
   parseable. **Self-validating**: md5 of the `OZNN` section must equal the head's baked `trunk_md5`, or
   load fails. **Emitted directly by the head trainer** going forward (it already holds the full trunk
   via `--trunk`); a small one-time **migration packer** fuses the existing OZUH 11M head (144afc8) +
   `nnue.bin` → OZNU so no retrain is needed. *(Exact byte layout settled in Goal A1.)*
   - `magic` = *what format* (constant), `run_id` = *which run* (provenance), `trunk_md5` = *identity for
     matching* — three separate jobs, three fields. The recognition magic stays constant so loaders work.
2. **C++ handle.** `UncertaintyNet` loads `OZNU`; `EvalWithDistribution()` reads the **shared, already-
   maintained accumulators** (H5's "ride the trunk for free" — never re-encode features), runs the
   **float** MDN forward, de-standardizes with baked `u_mean/u_std`, and returns `{ v_cp, mixture
   params, E[u|x], quantiles }`. The primitive is a **one-sided `Quantile(τ)`** (bisection over the
   mixture CDF — fine here, on-demand); a two-sided band is two reads. On-demand only → NPS irrelevant;
   this float path is the **golden reference** the later integer/grain head (H5-B) must match.
3. **C++ uncertainty harness.** Reads the curated FEN registry; per FEN emits `v` (engine-exact),
   mixture params, `E[u|x]`, quantiles at `C ∈ {.5,.8,.9,.95}`, **and `v*`** (fixed-depth deep search,
   datagen's path) → realized `u`, depth, nodes. Writes one structured results file under
   `experiment_results/unc-007/` (FEN + label + category + all of the above).
4. **Curated FEN registry** (checked in, `unc_research/positions/unc007_curated.txt`), ~20–30 positions,
   pre-registered categories each with a **written expectation**:
   - **expect-tight** — quiet/locked structures, simple K+P and drawn endgames → narrow `p(u|x)`, `E[u|x]≈0`.
   - **expect-wide** — sharp tactics, unresolved sacrifices, heavy imbalances → wide, heavy-tailed
     `p(u|x)` (the ν≈4 tactical tail unc-002 measured).
   - **expect-biased-mean** — known static-eval blind spots (fortresses, opposite-colored-bishop draws
     the eval overrates, long-term positional comp for material) → `E[u|x]` non-zero, **direction pre-written**.
5. **Python analysis experiment.** Reads the harness results (no re-embedding — densities reconstruct
   analytically from the emitted mixture params), plots small-multiples grouped by category (density
   over `u` cp; lines at `u=0`, `E[u|x]`, realized `u`; shaded `C`-band; annotate `v` and corrected
   `v−E[u|x]`), and computes the quantitative summary below. Timestamped output dir + `plot_metadata.json`
   (git SHA, `nnue.bin` md5, head path), mirroring `generate_unc_plots.py`.

## Metrics / pass criteria (pre-registered)

- **P0 — Port parity (hard gate, H0-style).** C++ handle vs Python reference head (`train_unc_head.py`
  loading the same trunk+head) agree on `E[u|x]`, the quantiles, and mixture params within float
  tolerance on **every** curated FEN. Fails → port bug (most likely the embedding: clamp-to-[0,1],
  `/127` dequant, or STM=own / non-STM=opp concat order). Nothing downstream is trustworthy until green.
- **P1 — Conditioning direction (qualitative → tested).** Predicted spread (`q90−q10`, or IQR) is
  **larger for expect-wide than expect-tight**, by a pre-registered margin; confirm with a rank test
  (Mann–Whitney, one-sided) across the two groups.
- **P2 — Mean direction (H6 sign-check).** On expect-biased positions, `sign(E[u|x])` matches the
  pre-written correction direction; report agreement rate + a sign test.
- **P3 — Coverage (the quantitative anchor).** Across the set, realized `u` lands inside the predicted
  central `C`-interval at ≈ `C` rate, and the **PIT of realized `u` is ≈ uniform**. Coarse (`N~30`);
  reported with CI, framed as a sanity gate, not a substitute for unc-002/006 fold calibration.

## Interpretation / kill conditions

- **P0 fails** → deployed path is wrong; fix the port (this is exactly what P0 exists to catch) before
  reading any plot.
- **P1 fails** (sharp not wider than quiet) with unc-002 val calibration intact → the curated set is
  mislabeled *or* these positions are off-distribution vs training; cross-check against a val-set
  subsample run through the same harness.
- **P3 badly off but unc-002 val PIT was uniform** → curated FENs are **off-distribution** (generalization
  gap worth knowing before H1 leans on the head in unfamiliar positions).
- **All pass** → the deployed head behaves sensibly in the engine on human-interpretable positions;
  green-light the **grain-quantized integer handle (H5-B)** against this float golden reference, and the
  **single-heuristic margin wiring (H1 / unc-004)**.
